## 三、核心交互（开发时必须对齐）

### 3.1 编辑页时间线：固定中央指针 + 内容滚动

```
时间线（固定左列标签 52pt，不滚动）
├── 录音轨 34pt      3 段演示数据（名称 + 绿色波形）
├── 画中画轨 34pt    3 段演示数据（缩略画面 + 名称）
├── 主轨道 115pt     ← 合并为一条，三层共享同一时间轴
│   ├── 画面帧条 60pt
│   ├── 声音包络波形 40pt
│   └── 时间刻度 13pt（每 5 秒一个长刻度 + 文字）
└── 迷你概览条 30pt   中性灰波形 + 品牌蓝视窗框
```

**关键机制**
- 白色指针 `.tl-play` **固定在可视区正中央**（`left:50%`），**永不随内容移动**
- 三轨装在 `.track-stack` 内整体 `translateX()` 滚动，`PPS = 26px/秒`
- **点任意轨道的任意区块** → 三轨同步滚动 → 该区块**中心对准中央指针** → 蓝框 + 时长标签 → 悬浮菜单弹出
- `PPS`、`X(t)=t*PPS`、`scrollToT(t)`、`applyScroll()`、`centerT()` 是这套机制的核心函数

### 3.2 悬浮菜单

| 规则 | 值 |
|---|---|

| 垂直位置 | 紧贴**所点的那条轨道**上方 **6pt**；只有最顶轨（录音）上方无处可放时才落到下方 |
| 样式 | 圆角 12 蓝底胶囊，**图标(19pt) + 文字(10pt)**，删除键白底红字 |

| 关闭 | 点菜单之外的任何空白处（轨道空隙/迷你条/标签列/预览区/顶栏） |

**按轨道切换内容**

| 轨道 | 菜单 |
|---|---|
| 主轨 | 替换 / 波剪 / 上锁 / 复制 / 删除 |

### 3.3 两条素材流程

**替换**（换镜头，时长强制锁定）
```
编辑页选中片段 → 菜单「替换」
  → 素材库（选片）→ 视频预览（点「添加」）→ 片段选择（选区时长已锁定 = 被替换片段时长）
  → 点「完成」→ 只改该片段的 src，不改 a/b
```

**插入**（指针处前插视频）
```
编辑页主轨左端「摄像机」→ 选视频（单选）→ 截取（拖蓝把手选段）→ 点 ✓
  → 插入到指针所在片段「之前」，后续片段整体后移，TOTAL 实时增长
```

### 3.4 红区只在波剪页

- **编辑页**：主轨画面条、波形条、迷你条**全部中性色**，无红罩、无红色折叠线
- **波形剪辑页**：红=气口 / 绿=保留，点击红↔绿翻转，拖动波形滚动，**指针固定中央**
- 数据字段 `type` / `cuts[]` 仍保留（波剪页与导出统计依赖），只是编辑页不渲染

### 3.5 录音（底栏「录音」键）

**交互**
```
底栏「录音」键 → 原地弹出 76pt 大按钮（水平中心对准录音键，贴边自动收敛）
  ├─ 点按   → 红圈 2 秒倒计时（数字 2→1→0，倒计时中再点 = 取消）
  │            → 自动开录 → 再点停止
  └─ 长按   → 跳过倒计时立即开录（阈值 300ms）→ 松开即停

录音中：每 100ms 推进一次
  · recElapsed += 0.1，push 一个包络峰值（模拟人声，带停顿的随机游走）
  · tlScrollPx = (recT0 + recElapsed) × PPS − viewW/2  → 轨道同步滚动，指针恒定居中
  · renderRecLive() 只重绘录音轨（代价小），波形实时延伸

停止后：写回片段时长、算体积、TOTAL=max(TOTAL, b)、重建刻度尺与迷你条、
        自动选中该段并弹菜单、toast 报「时长 · 文件名 · 体积」
录完浮层**保持打开**（可连续录下一段），提示「再点继续录 · 点外部关闭」
```

**★ 录音格式：已定版 = 方案 A「标准」**

```js
const REC_FMT = { codec:'WAV', bits:16, rate:48000, ch:1, bitrate:0 };
//                                     ↑ 改这一处即可整体切换
```

| 项 | 值 |
|---|---|
| 编码 | **WAV PCM（无损）** |
| 位深 | **16 bit** |
| 采样率 | **48 kHz**（必须与视频一致，iPhone 原生 48k） |
| 声道 | **单声道**（口播足够，体积省一半） |
| 体积 | **≈ 5.6 MB / 分钟** |

**为什么是 A**
1. **采样率必须 48kHz** —— iPhone 视频原生 48kHz，用 44.1kHz 会在音画合成时触发重采样，音质先损失一道。
2. **剪辑母带必须无损** —— 核心流程是「标记气口 → 折叠 → 反复试听调整」，每次处理都有损失，有损格式会累积劣化。
3. **单声道足够** —— 口播 / 气口标注本就是单声道场景，立体声只会让体积翻倍。

**备选（如需切换）**

| 方案 | 改动 | 体积/分 | 适用 |
|---|---|---|---|
| B 高保真 | `bits:24` | 8.5 MB | 后期要大幅重塑 / 强降噪 |
| C 轻量 | `codec:'AAC', bitrate:256` | 1.9 MB | 素材库大量录音、要省空间 |

**数据落地**：录音段会写入 `recItems[]`，带 `fmt`（格式文本）、`size`（实测体积）、`peaks[]`（包络数组，用于画波形）。轨内块的 `title` 会显示格式与体积。

### 3.7 底部工具栏：按轨道上下文切换（v1.5.4 新增，v1.5.5 主轨扩为 10 键）

**核心心智**：底部按钮**永远作用于「当前框选的区块」**；主轨区块被拖动经过中央指针时**自动出蓝框**，无需先点选。

| 轨道 | 按钮（左→右） | 数量 |
|---|---|---|
| **主轨（默认）** | 切割 · 波剪 · 音量 · 画面大小 · 旋转 · 左右镜像 · 变速 · 复制 · 删除 · 录音 | **10** |
| **录音轨选中**（蓝框＋悬浮菜单） | 切割 · 音量 · 复制 · 录音 · 删除 | **5** |
| **画中画选中**（蓝框＋悬浮菜单） | 切割 · 音量 · 替换 · 画面大小 · 旋转 · 左右镜像 · 变速 · 复制 · 删除 | **9** |

**自动蓝框**：`applyScroll()` 末尾调用 `autoFrameMain()` —— 取 `centerT()` 落在哪个主轨区块内，就把 `selectedId` 设成它并重绘 `.tframe`。只在**跨过区块边界**时才重绘（用 `id===selectedId` 提前 return），不是每像素重绘。

**关键实现约束**（别改回去，见「已知的坑」12/13）：
- `selectBlock()` 里的 `scrollToT(t, false)` 第二参**必须为 false**：程序化滚动时自动蓝框要让位，否则滚动被夹紧时会把「复制出的新段」的选中状态覆盖回指针下的旧段。
- `#phone` 的 pointerdown 白名单**必须包含 `#bottombar` 与 `#toolPanel`**：否则按下底部按钮的瞬间就 `clearSel()`，`selectedId` 被清空，音量/变速等拿到空目标会直接静默 return（表现为「点了没反应」）。

**工具面板**（音量 / 变速 / 画面大小）：底部浮出，黄色滑块 + 数值框 + 静音键（仅音量）+ `✕ / ✓ / ⌄` + 居中白色「应用到全部」胶囊。确认即写回 `vol` / `speed` / `scale`（`vol=0` 时 `muted=true`，主轨落静音标）。

**画面类参数**（画面大小 / 旋转 / 左右镜像）：`visualOf(track)` 统一取「参数载体」——主轨取 `regions` 里当前框选段，画中画取 `pipItems` 里当前选中块，录音轨无画面返回 `null`。三个函数 `openSize / rotateVis / flipVis` **主轨与画中画共用同一套实现**（`rotateVis`/`flipVis` 每次 +90° / 取反），结果由 `applyCanvasTransform()` 打到预览画面 `.canvas .frame-img` 上，并在角标 `#pipBadge` 显示 `90° · 镜像 · 120%`。**逐片段存储**（`scale/rot/flip` 挂在各自区块上），复制片段时随深拷贝一起带走。

**底栏横向可滑**：按键变多后（主轨 10 个 × 42px ≈ 420px）超出 430pt 屏宽，靠 `.bottombar{overflow-x:auto}` + `.bb{flex:0 0 auto}` 横向滚动，**不换行、不压缩**。

**导出键已移出底栏**：入口剩 **nav** 与 **编辑页顶栏 ⬆**（`ex.mjs` 已按此更新）。

### 3.8 变速面板（v1.5.6 新增 / v1.5.7 收敛为纯线性）

竞品的变速不是连续滑块，而是**离散档位 + 刻度尺 + 时长联动**，本轮按其形态实现。
**v1.5.7 起按需求只保留线性（常规）变速，顶部「曲线 / 常规」Tab 栏整体移除**（只剩一个选项时 Tab 栏是冗余 chrome），
连同 `.spd-tabs / .spd-tab` 样式与 Tab 点击绑定一并清掉，不留孤儿 CSS（见坑 7）。

| 元素 | 规格 |
|---|---|
| 档位行 | `0.1x · 0.5x · 1x · 1.5x · 2x · 3x · 4x` 共 7 档；选中档 **黄底 `#EAC54F` + 深色字** |
| 刻度尺 | 41 根刻度（每 5 根加长），**对数映射**把 0.1~4x 铺满；游标 `#EAC54F` 可拖 |
| 时长 | 面板左上「时长 x.xxs」，**随档位实时联动**（时长 = 原始时长 ÷ 倍速） |
| 底部三键 | `✕` 取消 / `✓✓` 应用到全部 / `✓` 确定（accent 高亮） |

**档位吸附**：`snapSpd()` 取最近档位，**差值 < 0.06 才吸附**，否则保留连续值 —— 所以拖刻度尺可得到 1.3x 这类非档位值，此时无档位高亮。

**对数映射的必要性**：`spdToPct/pctToSpd` 用 `ln` 在 0.1~4x 之间插值。若用线性，0.1~1x 会挤掉 87% 的刻度，2x~4x 全部糊在一起。

**变速会真实改变轨道结构**（不是只打个标记）：
- `时长 = 原始时长 / 倍速`，片段 `b` 改写；
- 主轨片段**连续**，故按 `delta` **平移后续所有片段**，`TOTAL` 同步增减并重建刻度；
- 相邻片段仍首尾相接（`seg0.b == seg1.a`）；
- `bBase` 锁存 speed=1 时的原始时长，保证重复调速**幂等**（见坑 15）。

**录音轨不支持变速**（无画面），底栏也不出该键。

## 六、⚠️ 接入真实数据时要注意

本原型是**纯静态演示**，所有数据在内存，**刷新即重置**：

| 数据源 | 内容 | 被谁消费 |
|---|---|---|
| `regions[]` | 主轨片段：`{id, type, a, b, src, locked, muted, cuts[], vol:100, speed:1, bBase, scale:100, rot:0, flip:false}` | `renderThumbs` / `renderWave` / `renderMini` / 导出统计 |
| `pipItems[]` | 画中画片段：`{id, a, b, src, vol:100, speed:1, scale:100, rot:0, flip:false}` | `renderSideTrack('pip')` / `applyCanvasTransform` |
| `recItems[]` | 录音片段：`{id, a, b, src, fmt, size, vol:100}` | `renderSideTrack('rec')` |
| `wcSeg[]` | 波剪页红绿分段（28 段 × 0.25s） | `renderWcut` |
| `TOTAL` | 轨道总时长（秒，**动态**：复制/插入会增长） | 所有滚动/换算 |
| `PPS` / `WC_PPS` | 像素密度（26 / 110 px/秒） | 所有位置换算 |

**建议**：接入真实数据时替换上述数据源与 `render*` 函数，**不要改动 UI 结构与 CSS 变量**。

### 已知的坑（都踩过并修好了，别改回去）

1. **ENV 长度**：`renderWave` 里必须 `if(!ENV || ENV.length < n) ENV=genEnv(n)` 并用 `ENV[i%ENV.length]` 访问 —— 否则 `TOTAL` 增长后索引越界会产生 `NaN` 的 path。
2. **id 对不上会静默失效**：`.sheet` 自身是 `display:none`，打开抽屉必须**遮罩与 `.sheet` 同时加 `show`**。
3. **flex 压缩溢出**：主轨道三层必须写 `flex:0 0 <固定高>`，否则会被压扁并被底栏盖住。
4. **滑杆状态串台**：统一用 `placeExSlider('exRes')` 传 `'exRes'`，函数内已做 `isRes` 归一化。
5. **每个可点元素都要有真实功能**，不能只弹 toast —— "点了没反应"和"功能坏了"用户分不出来。
6. **静态检查用 `node --check`，不要用 `new Function()`** —— 后者对「`function foo()` 与 `let foo` 同名」这种重复声明**不报错**，会让整个脚本在浏览器里静默挂掉（全站白屏）。
7. **组件形态变了要清旧 CSS** —— 例如悬浮菜单从圆形按钮改成方块键后，老的 `background:rgba(255,255,255,.94)` 白底规则会留成孤儿样式，视觉上就是"凭空多出的白方块"。
8. **录音按钮要加入「点空白关菜单」的白名单** —— 否则 pointerdown 冒泡到 `#phone`，会清掉刚 `selectBlock('rec', …)` 选中的片段。
9. **任何「蓝框/选中框」元素，CSS 默认 `display:none` 时，渲染处必须显式 `display:block`** —— 主轨 `.tframe`、画中画 `.psel`、录音 `.rsel` 都踩过：元素渲染进 DOM 却因 CSS `display:none` 永不显示，表现就是「点了没蓝框」。
10. **迷你概览条的视窗蓝框（`#miniView`）必须可拖** —— 它只是 `applyScroll` 算出的显示，本身没有拖拽监听；不挂 `pointerdown/move` 的话，用户「拖蓝框移动轨道」这个直觉交互就失效。
11. **改 CSS 时绝不能留下孤立的 `}`** —— 上一轮给 `.mini` / `.mini .selb` 补属性时，在 `}` 之后又跟了一行声明（形如 `border:…; overflow:hidden;}` 后面又接 `border:1px…;`），导致这两条规则提前闭合、后续声明变成「孤儿规则」，进而**连带破坏了排在后面的 `.floatbar{display:none}`**。症状极隐蔽：菜单在未选中时就以全宽块显示、且点画中画/录音选不中（表现像"菜单坏了"）。**改完 CSS 务必跑 `verify/cssverify.mjs` 校验 `.floatbar` 默认 `display:none`、高度 0**；也可加一条 `node -e` 统计 `{` 与 `}` 数量是否相等。
12. **底栏与工具面板必须进「点空白关菜单」的白名单** —— `#phone` 的 pointerdown 里那条 `closest(...)` 白名单，v1.5.4 起必须含 **`#bottombar` 与 `#toolPanel`**。漏掉时症状是：底部按钮**全部静默失效**（音量/变速面板弹不出来、切割删除找不到目标）。原因：`pointerdown` 先于 `click` 触发，`clearSel()` 已把 `selectedId` 清成 `null`，等 `click` 里的 `openVolume()` 执行时 `regions.find(...)` 拿到 `undefined` 就 `return` 了 —— **不报错、无提示**，极难定位。
13. **程序化滚动要让位自动蓝框** —— `scrollToT(t, autoFrame)`：凡是 `selectBlock` 这种「为了对准某个区块」的滚动，必须传 `false`。否则滚动被边界夹紧时，指针并不在目标区块上，`autoFrameMain()` 会把 `selectedId` 改写成指针下的**旧**区块，把刚做的显式选中吃掉（症状：`wf.mjs` 里「复制体被自动选中」失败，选中停在原段）。用户手动拖轨道 / 拖迷你条时仍走默认 `true`，保持自动蓝框。
14. **测试脚本里先收起录音浮层再拖轨道** —— `#recPop` 是刻意的可交互浮层（`bottom:92px`、`z-index:75`、`pointer-events:auto`），展开时正好压在时间轴底部。`smoke.mjs` 若先点了底栏「录音」再拖轨道，`elementFromPoint` 会命中 `recpop` 导致拖动无效（误报 `[scroll] 拖动轨道内容未滚动`）；拖拽前先关掉它即可。
15. **凡是「按比例改时长」的功能，必须锁存原始时长（`bBase`），不能拿当前 `b-a` 当基数** —— 变速后 `b-a` 已经缩短，若二次打开面板时再用 `b-a` 当原始时长，就会**重复累乘**（实测 7s → 2x 后 3.5s → 再开面板变 1.75s，而不是稳定在 3.5s）。写入时 `bBase` 只在首次赋值，之后 `nd = bBase / speed`。
16. **改 `TOTAL` 的操作要重新锁住选中态** —— 变速会改 `TOTAL` → 触发 `applyScroll()` → `autoFrameMain()` 重新框选指针下的区块，于是**用户刚编辑完的区块被自动蓝框抢走**，下次开面板回显错档位。`applySpeed()` 里在 `id != null` 时用 `autoFrameLock=true` 包住重渲染，并 `setSelId()` + `scrollToT(..., false)` 显式复位。
