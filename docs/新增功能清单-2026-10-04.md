## N0 · `BKTimeline` 段模型（地基，最先做）

### 是什么
时间轴的存储模型从「存切点」升级为「存段」：

```
Segment { start: Double, end: Double, state: .keep | .cut }
Timeline = 有序段的数组，覆盖 [0, duration]，互不重叠、首尾相接
```

- 初始状态：检测出的气口 = `.cut`（粉红），说话段 = `.keep`（绿）。与现有 `keepRanges` 等价，只是显式成段。
- **`.cut` 段的源区间永远保留**——这就是皓哥说的「缓存」。折叠只是渲染/播放时跳过，**不销毁源时间**。
- 最短段保护：单段 < **0.1s** 不允许（把手夹到 0.1s 即停），防碎成无数小段。

### 改动清单
- [ ] `BKTimeline` 增加 `Segment` 结构与 `segments` 存储
- [ ] `keepRanges` / `cutRanges` 改成从 `segments` **派生**（`computed`），不是独立存储
- [ ] `normalize` 保持既有铁律：首尾夹 `[0, duration]`、相邻严丝合缝、无零宽
- [ ] 段模型随 `BKDraftStore` **落盘字段同步**（草稿序列化要能读回旧草稿）
- [ ] **纯逻辑按铁律先在 `tools/preview_cut.py` 用 Python 复刻 + 随机不变量验证**，全绿再写 Swift
      （不变量：从 0 开始 / 到 duration 结束 / 相邻严丝合缝 / 无零宽）

### 验收
- [ ] 旧草稿能正常读出，不崩
- [ ] 随机几千组脏数据跑 normalize，不变量全绿
- [ ] `keepRanges` 与改动前**行为完全一致**（删红功能还没接，不能影响现有导出）

### 风险
🔴 **高**。这是全局数据结构改动，`keepRanges` 被导出、预览、联播、轨道渲染共用。
必须**先只发 N0 回归一遍**（1.2.x 的老功能全部照常），再往上叠 N1~N5。

## N1 · 一键删红键（替换「反转键 `⟳`」）

### 入口
工具栏上**替换反转键 `⟳` 位置**的删红键，**不额外加键**。
（皓哥 2026-10-04 定：替换的是反转键，不是联播键也不是别的。）

### 图标（终定）
自定义 `UIImage` 绘制，非系统符号：
- **方案 B · 错位重叠双 X**（两个 X 对角错位、中间交叠，像「✕✕」）
- 红色 = **纯红 `#FF3B30`**
- 见 `docs/删红键图标.svg`（方案 A 标「备选」留档）

### 行为
1. 所有 `.cut` 段标记为「已折叠」（保留源区间，仅渲染/播放跳过）
2. 绿区按原顺序 **ripple 拼接**，`trackContainer` 渲染成一条连续绿轨，**时间轴总时长 = 各绿区之和**，变短
3. 绿区与被删区域边界保留为可拖手柄（供日后把已删素材拖回成绿 = N4）
4. 状态行提示「已删除 N 段气口，保留 M 段」

### 与联播的分工（别打架）
| 动作 | 对轨道 | 播放 ▶ | 播放联播 `\|▶\|` |
|---|---|---|---|
| **联播**（已有） | **不改轨道** | 原片全播 | 跳红区、只放绿（预演成品） |
| **删红键**（新增） | **真折叠**：绿区 ripple、时间轴变短 | 自然只放绿 | 无红可跳 |

一句话：联播是「不改轨道的试看」，删红键是「把试看**提交**成新轨道」。两者并存。

### 改动清单
- [ ] 绘制红双 X 自定义图标（`BKIcons` 走新入口）
- [ ] 工具栏按钮：删 `invertButton`，换成 `deleteRedButton`（注意工具栏按钮数组 `applyToolStyle`/禁用态/布局那几处都要跟着改）
- [ ] 点击 → 折叠 `.cut` 段 + ripple 重排 + 状态行提示
- [ ] **ripple 后的时间轴要能被 N2~N5 正确渲染**

### 验收
- [ ] 按一次，全轨变绿、无粉红、时间轴变短
- [ ] 状态行报「已删除 N 段气口，保留 M 段」，数字对
- [ ] 导出结果 = 只含绿区内容（与联播预演一致）
- [ ] 折叠后拖接缝能把已删素材拖回（= N4 联动）

### 风险
中。涉及工具栏重组（`invertButton` 引用点较多，注意全搜干净）。

## N3 · 长按区域编辑态（黄边 + 两端黄把手）

### 手势分工（与 N2 不冲突）
| 手势 | 结果 |
|---|---|
| **短按（tap）** | 该区 绿 ↔ 红 切换（N2） |
| **长按（约 0.5s）** | 进入编辑态：黄色边框 + 两端各一个黄色拖拽把手 |
| **拖把手** | 增删该区边界（N4） |

> 为什么长按而不用「直接拖分割线」：接缝手柄藏在两段之间，用户不知道从哪拖；
> 长按先让区域亮起来，意图更清晰，且与短按切换红绿分工明确。**已拍板。**

### 视觉规格（数值已定，照抄）
- 选中区边框：**黄色 `#EF9F27`，3pt**
- 把手：竖直黄条，**宽 16pt**，上下各**探出轨道 10pt**，中心一个**白色抓点**
- 触控区：每个把手外围 **≥ 44×44pt**（满足 44pt 触控目标）
- 退出编辑态：点别处 / 松手后延迟一小段再收（避免拖到一半误退）

### 改动清单
- [ ] `UILongPressGestureRecognizer`（约 0.5s）挂在 canvas，与现有 tap / pan 三指手势**互相排他**
      （注意：现有 `pan` 已经用 `gestureRecognizerShouldBegin` 抢滚动，longPress 要加进同一套仲裁）
- [ ] 编辑态渲染：黄边 + 两把手（在 `TrackCanvas.draw` 里画，或做成独立 overlay 层）
- [ ] 淡入淡出动画（150~200ms）
- [ ] `UIImpactFeedbackGenerator` 轻震
- [ ] VoiceOver：「延长/缩短 开头（结尾）」

### 验收
- [ ] 长按任意区 → 该区亮黄边 + 两端出黄把手，其余区不受影响
- [ ] 短按仍然只是切红绿，**不误触发编辑态**
- [ ] 拖把手时**不触发滚动**（现有 `pan` 的 `isScrollEnabled` 那套逻辑要复用）
- [ ] 黄色 = `#EF9F27`，和阈值虚线、状态行警告色同一套色

### 风险
中。**三指手势仲裁是主要风险点**——长按/拖动/滚动三者必须互不干扰。

## N4 · 把手拖拽增删边界

### 把手语义（「该区」可绿可红，把手是标准区域边缘裁剪）
- **左把手（该区开头端）**：往左拖 = **增加开头**；往右拖 = **减小开头**
- **右把手（该区结尾端）**：往右拖 = **增加结尾**；往左拖 = **减小结尾**
- 拖动扫过的区域变为「该区同色」

### 越界约束（不越资产边界）
- 该区始于**原视频开头**（`start = 0`）→ 左把手往左拖**不增加**；往右拖仍可减小开头
- 该区止于**原视频结尾**（`end = duration`）→ 右把手往右拖**不增加**；往左拖仍可减小结尾
- 区域最短 **0.1s**（把手夹到 0.1s 即停）

### 实现要点
- 拖动中实时重拼预览合成体、播放器跟随 seek，**不重编码**（复用 `BKExporter` 拼段）
- 拖动中降采样渲染（与 bug ② 的性能优化同批做，见 `待改代码清单-2026-10-04.md`）

### 改动清单
- [ ] 左/右把手拖动 → 改该段 `start` / `end`
- [ ] 三重夹取：资产边界、相邻段不越界、最短 0.1s
- [ ] 扫过区域继承该区 `state`（绿拖出绿、红拖出红）
- [ ] 拖动中实时预览（播放器 seek + 预览合成体重拼）
- [ ] 松手时**合并成一次撤销**（拖动过程不入栈，这是 v1.1.x 已有机制，沿用 `boundaryCommitted`）

### 验收
- [ ] 往左拖左把手 → 开头变长、该区变大
- [ ] 往右拖左把手 → 开头变短（**可减，不只增**）
- [ ] 开头段往左拖**不增加**（0 之前没素材）
- [ ] 结尾段往右拖**不增加**
- [ ] 拖到 0.1s 就停住，松不过去
- [ ] 拖绿区拖出绿区、拖红区拖出红区
- [ ] **一次拖动 = 一步撤销**（不是拖一次退一帧）

### 风险
中。撤销合并 + 边界夹取要一起想清楚。

## N5 · 删红后只播绿区预览

### 是什么
删红键提交后主轨道已只剩绿区 → 点 ▶ 即只放绿区、带声音、自动接上（**无需特殊处理**）。
未提交、只想试看 → 用联播 `|▶|`（不改轨道、跳红区预演成品）。

### 实现
播放用 `AVMutableComposition` 按当前 `.keep` 段拼（视频+音轨都拷），直接给 `AVPlayer` 播；
**不重编码**，复用 `BKExporter` 的拼段函数。

### 改动清单
- [ ] 把 `BKExporter` 的拼段函数抽成 `buildComposition(keepRanges:)`，导出与预览共用
- [ ] 预览播放器接折叠后的段

### 验收
- [ ] 折叠后点 ▶ 播的正好是绿区内容，带声音
- [ ] 和联播 `|▶|` 预演出来的效果一致

### 风险
低。但要注意**别和 bug ③（联播起点单位错配）混在一起改**——那是 `startKeptTime` 的问题，
本功能是播放内容，别顺手把 `jointTapped` 也改了，查不出是哪处引起的。

## 施工顺序（严格按依赖）

```
第 1 步  N0  段模型改造         → 发版回归（1.2.x 老功能必须全绿）
第 2 步  N2  点段 toggle 适配新模型 → 可与 N1 同批
第 3 步  N1  删红键 + N5 只播绿区   → 主功能落地
第 4 步  N3  长按编辑态           → 手势仲裁
第 5 步  N4  把手拖拽增删         → 收官
```

理由：
1. **N0 单独发一版**——它是全局数据结构改动，崩了/行为变了要能立刻定位是老模型还是新功能的问题
2. **N1+N5 同批**——删红后立刻能看到「只播绿区」的效果，闭环完整
3. **N3→N4 顺序不能反**——把手是 N3 编辑态里才出现的，N4 依赖 N3 的产物
