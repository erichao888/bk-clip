## 一、概念重定义（最重要）

| 旧概念 | 新概念 | 差别 |
|---|---|---|
| 切割（cut） | **标记（mark）** | 只是画一道线，**不动数据** |
| 删除红区 | **折叠红区** | 把一段区间收窄成一条线，**内容还在** |

**轨道上从来没有「删掉」这回事。** 只有「标记」和「折叠」。

## 二、三阶段流程（皓哥手绘图）

```
阶段一 · 标记
    [区域1]  [A ┃ 区域2(红区) ┃ B]  [区域3]
              ↑                  ↑
         A = 红区起点标记     B = 红区终点标记
    轨道完整，没有切割。A、B 只是被标记下来。

阶段二 · 折叠（按「折叠键」= 原「删红键」）
    [区域1]  [区域3]
              ↑
    区域2 被折叠成一条线。A 与 B 视觉重合，
    但仍是两个独立的时间点。轨道变短。

阶段三 · 拖动（点选片段 → 黄框 → 拖把手）
    [区域1 变长]  ┊  [区域3]
                   ↑
    拖区域1 右端到 C：
      区域1 结束标记 A → C
      区域3 开始标记 仍是 B（不动）
      露出的量 = C − A（从折叠区多显露出来的那一截）
      折叠区剩余 = B − C
```

## 三、数据模型

### 记录 A · 红区标记（第一阶段）
```
redRanges: [(A, B)]   // 原片时间，第一阶段可拖边缘调整
```
冻结于按下折叠键的那一刻。

### 记录 B · 折叠标记（第二阶段）
```
每道折叠线存**两个**可调标记点：
    leftMark  = 左区块的结束时间   （初始 = A，可拖到 C）
    rightMark = 右区块的开始时间   （初始 = B，可拖）
```

**这是与旧实现的根本差异**：旧实现一道缝只存**一个**点（后块的 start），
丢了左区块的结束时间 → 拖把手时右块不感知 → 黄框错位、箭头方向分不清。

### 推导量
```
折叠长度[i] = rightMark[i] − leftMark[i]      // 有真实时间跨度，不是 0
显示总长    = 原长 − Σ 折叠长度[i]            // 动态，每次拖动都会变
保留区块    = [0, leftMark[0]]
              [rightMark[0], leftMark[1]]
              ...
              [rightMark[n−1], 原长]
```

## 四、约束（皓哥 22:30 确认）

| 约束 | 规则 |
|---|---|
| **C ≤ B** | 左端往右拖，最多与 B 重合，**不能越过** |
| **≥ A** | 左端往左拖，最早与 A 重合，**不能更早** |
| 右端同理 | 往左最早到 A，往右最远到 B |
| 折叠线视觉宽度 | **与橙色指针同宽**（约 2pt） |
| C == B 时 | 折叠区长度 = 0，两块完全拼合 |

## 五、坐标映射（待实现，是整套交互的地基）

**两个时间轴**：
- **原片时间轴**：0 ~ 原长，永不改变
- **折叠后时间轴**：0 ~ 显示总长，屏幕用这条

```
屏幕布局：
    保留区块 j 占宽 = 其时间长度 × pps
    折叠线  i 占宽 = 线宽（≈2pt，不是 0！）

轨道总 px = (原长 − Σ折叠长度) × pps + 折叠线数 × 线宽
```

**双向换算**：
```
原片时间 → 折叠后时间：减去该点之前所有折叠长度
折叠后时间 → 原片时间：加上该点之前所有折叠长度
```

⚠️ **必须先用 Python 复刻验证不变量**（从 0 开始、连续无空洞、不越界），
全绿了才写进 Swift。参考 `tools/preview_cut.py` 的做法。

## 六、交互流程

### 6.0 ⭐ 触发方式铁律（23:13 定 → **23:19 重大修正**）

**23:19 修正**：红绿切换从「点轨道」改为**界面上的独立按钮**，由此**释放了点击（tap）**。
交互模型因此改成和竞品一致：**点选片段即进编辑态**，不再用长按。

| 手势/控件 | 作用 |
|---|---|
| **红绿切换按钮**（界面独立按钮，不放轨道上） | 切换**当前选中区块** 红 ⇄ 绿 |
| **点选片段（tap）** | 进入编辑态：黄框 + 两端把手 + 悬浮工具条 |
| 拖把手 | 改标记点，从折叠区露出 / 收回一截 |

> ⚠️ **之前定的「长按进编辑」作废**（那是 23:13 红绿还占着点击时的临时方案）。
> 现在点一下就进编辑态，和竞品一样。长按不再承担进编辑职责。

### 6.1 红绿切换按钮（独立控件，释放了 tap）

```
点「红绿切换」按钮
  → 当前选中的区块在 红 ⇄ 绿 之间切换
  → 不进编辑态、不改时间标记、不弹浮条
```
（按钮长什么样、放界面哪个位置待 UI 定，但**绝不绑在轨道点击上**。）

### 6.2 点选片段 → 进编辑态

```
点一下某保留区块
  → 黄框（罩住**整个**区块）+ 两端把手（‹ ›，在框外）
  → 片段正上方弹出**悬浮工具条**（黄底白圆钮，锚定在片段上方）
  → 拖把手 = 改该区块的起始/结束**标记点**
  → 视觉上从相邻折叠区多露（或少露）一截
  → 折叠区长度变 → 轨道总长同步变
  → 点空白处退出编辑态
```

### 6.3 底部工具栏（界面最下方，**可左右滑动**）

- 固定在**界面最下方**（不是悬浮在片段上方那一条）。
- **横向可滑动（scroll）**：图标多时滑出更多，解决「一排放不下」的尴尬。
- 内容随选中对象变化（如滤镜 / 截取 / 特效 / 剪切 / 删除 / 拷贝 / 抠图 / 画质 …）。
- 与「片段上方悬浮工具条」是**两套**：
  - 上方悬浮条 = 作用于**该片段**的原子操作（替换 / 加帧 / 曲线 / 锁定 / 复制 / 删除）
  - 底部栏 = 全局 / 上下文工具，**可横滑扩展**

## 七、导出（皓哥 22:40 定，最后实现）

**分离导出 + 长度校验 + 两次重试报错**：

```
1. 视频：按时间标记逐段导出，拼成完整视频轨
2. 音频：按时间标记逐段导出，拼成完整音频轨
3. 比对两条轨的长度
   ├─ 一致 → 合成 MP4 输出
   └─ 不一致 → 返回重新生成
4. 连续两次比对仍不一致 → **报错并停止**（绝不无限重试、绝不能崩）
```

**这套设计的意义**：根治音画同步 ——
**不手算任何 PTS**（前三次修复全错在猜帧长/块长），
改为让系统各导各的，**用长度校验兜底**，对不上就明确报错而不是卡死或崩进程。

对应旧笔记里的音画同步铁律：三次错误全因「游标推进量 ≠ 实际写入的样本」，
且阈值是猜的（B帧 DTS≠PTS、duration≠帧长、块长≠1024/48000）。
新方案绕开这一切。

## 八、与旧实现的差异清单（改代码时逐条对照）

| 项 | 旧（v1.4.8） | 新（v2.0.0） |
|---|---|---|
| 轨道时间轴 | **原片时间**（duration 不变） | **折叠后时间**（原长 − Σ折叠长度） |
| 折叠区存储 | 无（隐含在绿区相邻关系里） | **显式区间**，含两个标记点 |
| 折叠区视觉 | 固定 1~4pt 装饰线 | **有真实长度**，压成指针宽 |
| 拖把手语义 | 改绿块自己的两端 | **改标记点**，从折叠区露出一截 |
| 两块关系 | 各自独立，会互相侵入 | 中间永远隔着折叠区，不会重叠 |
| 导出 | 单条 composition | **视频/音频分离 + 长度校验** |
