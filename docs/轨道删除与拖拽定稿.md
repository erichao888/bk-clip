## 2. 删红键 与 联播 的区别（先讲清，免得打架）

| 动作 | 对轨道的影响 | 播放 ▶ | 播放 联播 `\|▶\|` |
|---|---|---|---|
| **联播**（已有） | **不改轨道**，红区仍在 | 原片全播（红绿都放） | 跳红区、只放绿（预演成品） |
| **删红键**（新增） | **真折叠红区**：绿区 ripple 拼接、时间轴变短；红区源区间保留待恢复 | 时间轴已无红，自然只放绿 | 同左（无红可跳） |

一句话：联播是"不改轨道的试看"，删红键是"把试看结果**提交**成新轨道"。两者并存，用户各取所需。

## 3. 数据模型（改动落在 `BKTimeline`）

按工程铁律「时间线改动只走 `BKTimeline`」，时间轴由"存切点"升级为"存段"：

```
Segment { start: Double, end: Double, state: .keep | .cut }
Timeline  = 有序段的数组，覆盖 [0, duration]，互不重叠、首尾相接
```

- 初始：检测出的气口 = `.cut`（粉红），说话段 = `.keep`（绿）。与现有 keepRanges 等价，只是显式存段。
- **`.cut` 段的源区间永远保留**（这就是用户说的"缓存"）——折叠只是渲染/播放时跳过它，不销毁源时间。
- 最短段保护：单段 < **0.1s** 不允许（拖动手柄夹到 0.1s 即停），防碎成无数小段。（默认值，可调）

## 4. 三个功能

### 4.1 一键删红键（替换「反转键 `⟳`」）

- 入口：工具栏上**替换「反转键 `⟳`」**位置的**删红键**（不额外加键，皓哥 2026-10-04 定：替换的是反转键，不是联播键）。
- **图标（皓哥 2026-10-04 定，终选）**：自定义红色图案 = **两个重叠交错的红 X**，非系统符号；见 `删红键图标.svg`。**终选：方案 B（错位重叠双 X）**，红色 = 纯红 `#FF3B30`（不换 app 红区粉红）。实现时为自定义 `UIImage` 绘制。
- 行为：
  1. 把所有 `.cut` 段标记为"已折叠"（保留源区间，仅渲染/播放跳过）。
  2. 绿区按原顺序 **ripple 拼接**，`trackContainer` 渲染成一条连续绿轨，**时间轴总时长 = 各绿区之和**，变短。
  3. 绿区与原时间轴上被删区域的**边界保留为可拖手柄**（见 4.3），供日后把已删素材拖回成绿。
  4. 状态行提示「已删除 N 段气口，保留 M 段」。

### 4.2 点段 toggle 绿↔红（沿用定稿第 5 节）

- 点主轨道上的某一段 → 该段 `.keep` ↔ `.cut` 切换（粉红↔绿），无声，画面可跳到该段起点（沿用现有行为）。
- 意义：一段绿区想被删，先点它变红（`.cut`），再按删红键一并清掉。满足"只能删红区"。

### 4.3 区域编辑模式（长按进入，2026-10-04 再细化）

**手势分工**（与 4.2 点段 toggle 不冲突）：
- **短按（tap）区域** → 该区 绿 ↔ 红 切换（沿用 4.2）。
- **长按（约 0.5s）区域** → 进入编辑态：黄色边框（`#EF9F27`，3pt）包住该区，两端各出一个**黄色拖拽把手**（样式尺寸见图 `拖拽把手样式.svg`）。

**把手语义**（「该区」可绿可红，把手是标准区域边缘裁剪）：
- **左把手（该区开头端）**：往左拖 = **增加开头区域**；往右拖 = **减小开头区域**。
- **右把手（该区结尾端）**：往右拖 = **增加结尾区域**；往左拖 = **减小结尾区域**。
- 拖动扫过的边界区域变为「该区同色」（绿区拖出绿、红区拖出红）。

**边界约束（不越资产边界）**：
- 该区始于**原视频开头**（start = 0）：左把手往左拖**不增加**（0 之前没素材）；往右拖仍可减小开头。
- 该区止于**原视频结尾**（end = duration）：右把手往右拖**不增加**；往左拖仍可减小结尾。
- 区域最短 **0.1s**（防碎段）。

**实现要点**：
- 拖动中实时重拼预览合成体、播放器跟随 seek，**不重编码**（复用 `BKExporter` 拼段）。
- `UIImpactFeedbackGenerator` 轻震；VoiceOver：「延长 / 缩短 开头（结尾）」。
- 删红键折叠红区后，绿区 ripple 拼接；被折红区边界仍可经长按相邻绿区进入编辑、把已删素材拖回成绿（恢复）。

#### 4.3.1 拖拽把手样式与尺寸（图）

见 `docs/拖拽把手样式.svg`。要点：
- 颜色：黄 = 警告色 `#EF9F27`（与阈值虚线、状态行警告色同一套，配色统一）。
- 把手：竖直黄条，宽 16pt，上下各探出轨道 10pt，中心一个白色抓点。
- 触控区：每个把手外围 ≥ 44×44pt（虚线示意），满足 44pt 触控目标。
- 选中区：3pt 黄边。

> 注：本模型取代早先「接缝手柄只增不减」的设想——改为**每区独立编辑把手、可增可减**，与剪映一致；粉红只来自检测标红或手动 toggle。

## 6. 与现有交互的衔接（待实现时注意）

| 现有项 | 本定稿的处理 |
|---|---|
| 4.5「主轨道画的是原片时间轴」 | 删红**前**仍是原片时间轴（含粉红气口）；删红**后**渲染为 ripple 拼接的绿轨（时间轴变短）。属对 4.5 的**补充**，非推翻 |
| 阈值滑杆 / 吸管重算 | 重算会重新产生 `.cut` 段（覆盖手动 toggle）；手动 toggle 优先于上一次检测，直到再次吸管 |
| 联播指针跨红区（4.5.4 第 499 行） | 删红后无红可跨，联播退化为直放；逻辑不变 |
| ✕ 移除按钮（v1.1.6，删整条素材） | 不受影响，仍是"从本批移除这条视频"，与轨道内删红区是两回事 |

1. `BKTimeline`：切点模型 → 段模型（`{start,end,state}`），`normalize` 仍首尾夹 `[0,duration]`、相邻严丝合缝。

4. 状态行：复用现有 `statusLabel`，文案「已删除 N 段气口 / 恢复 1 段」等。
