## 0. 一句话结论 + 范围必须拍板（最重要）

你给的 Batch 2 三个目标里，**目标①（编辑器吃 v2）和目标③（删 `BKModels.swift` + `Drafts/`）不能在同一批里孤立完成**。

原因：v1 数据模型 `BKProject` / `BKDraftBatch` 被**不止编辑器**消费 —— 导出面板、导出器、联播/合成构建器、网格「直接导出」、起始页桥接、以及 `BKDraftStore` 的 v1 落盘路径全都依赖它。只把编辑器改吃 v2，其余消费者仍在吃 v1，于是 `BKModels.swift` 和 `Drafts/` **还不能删**，删了全工程编不过。

> 换句话说：**删模型是「全工程统一走 v2」的收尾动作，不是编辑器迁完就能做的**。

**建议把 Batch 2 拆成三块**（见 §1 耦合盘点 + §2 模块清单），范围由你拍板：

| 子批 | 内容 | 能否独立发版 | 完成后能否删 v1 模型 |
|---|---|---|---|
| **2A（本批优先）** | 波形剪辑页（波剪子页）迁 v2：读/写单个 `BKClipBlock.keptRanges`，删 `bridgeToV1` | ✅ 可 | ❌ 还不能（导出还在吃 v1） |
| **2B（主编辑页本体）** | 新建 v2 主编辑页：多片段主轨 + 自动蓝框 + 上下文底栏 10/9/5 键 + 波剪入口 + 录音/画中画轨 | ⚠️ 大，建议单独成批 | ❌ 还不能 |
| **2C（导出管线迁 v2 = 原 Batch 3）** | `BKExporter` / `BKExportPanelViewController` / 网格「直接导出」/ `BKDraftStore` 的 v1 路径全改吃 v2 主轨 | ✅ 可 | ✅ **只有 2C 完成才能删 `BKModels.swift` + `Drafts/`** |

**我的推荐**：2A 单独发一版（风险最小、能立刻去掉桥接），2B / 2C 各自成批。目标③放到 2C 之后。

## 2. 模块改动清单（改动点 / 风险点）

### M1 · `BKEditorViewController` 入口与状态（2A）
- **改动点**
  - `init(batch:index:asset:probeInfo:)`（L129）→ 改为 `init(draft: BKDraft, blockIndex: Int, asset: AVAsset, probeInfo:)`。
  - 删除 `batch: BKDraftBatch` / `itemIndex` / `var item: BKProject`（L147）/`history` 里存的 `BKProject` 快照，改为持有 `draft` + `blockIndex`，编辑操作直接改 `draft.track.blocks[blockIndex]`。
  - `prepareItem()`（L193）把 probe 几何写进 `item` 的写法，要改写到 **v2 块**。⚠️ 见 M11 模型缺口：`BKClipBlock` 目前**没有** `displayWidth/Height/rotation/thresholdDb/autoThresholdDb/sourceApplicable/playheadTime` 字段 —— 这些要么补到 `BKClipBlock`，要么改为导出/播放时实时 probe、UI 态不落盘。
- **风险点**：`finishSession()`（L207）的「整批没动刀就丢」逻辑，要映射到 `draft.everEdited`；封面生成 `BKCovers.generate(asset:at:)` + `BKCovers.save(img, batchId:assetId:)` 的 `batchId` 改 `draft.id`、`assetId` 改 `block.assetLocalID`（L229-232 已用 `item.assetLocalID`，改名即可）。

### M2 · 数据读写（2A）
- **改动点**：所有 `batch.items[itemIndex].xxx =` / `applyItem(_:BKProject)` / `commit(_:BKProject)` 改为操作 `draft.track.blocks[blockIndex]`。`BKDraftStore.shared.scheduleSave(batch)` → `scheduleSaveV2(draft)`；`flushIfNeeded()` / `cancelPending()` → `flushV2IfNeeded()` / `cancelPendingV2()`。
- **风险点**：`everEdited` **只置不清** 的语义要保持（v1 `applyItem` 里 `if updated.isEdited { batch.everEdited = true }`）。v2 的「动过刀」= `block.keptRanges.count > 1`（即 `isWaveCut`）或曾设过阈值/倍速。

### M3 · 波形分析 + 自动检测（2A，基本复用）
- **改动点**：`BKAudioAnalyzer.extractEnvelope` / `BKDetector.detect`（入 `envelope` + `srcDuration`）**完全不用改**，仍是逐素材。检测产出 `cuts` → 在波剪页里只作**显示用红区**，确认后 `commit` 成 `block.keptRanges`（绿区 = 红区补集）。
- **风险点**：v1 的 `thresholdDb` / `autoThresholdDb` / `sourceApplicable` 目前存在 `BKProject` 上。v2 若块不存这些字段，检测状态无法「恢复上次的编辑进度」+「恢复自动」。**必须拍板**（见 Q4）。

### M4 · 编辑操作映射到块 `keptRanges`（2A，核心差异）
v1 的两套记录（阶段1 红区 `marks` + 阶段2 绿区 `keptRanges` + `isStage2`）在 v2 **收敛成一个**：块只存 `keptRanges`（绿区），红区是波剪页里的**瞬时视图**（绿区的补集）。

| v1 操作 | v2 等价 |
|---|---|
| 自动检测 → `marks`(cut) | 检测出 `cuts` → 波剪页显示为红区（不入库） |
| 一键去红 `deleteRedTapped` → `deriveKeeps` → `keptRanges` | **入口即绿区**：打开波剪页若块未波剪，跑检测；确认后直接写 `block.keptRanges` |
| 点段 toggle 红绿 `togglePiece` | toggle 某区间的红/绿 → 重算 `keptRanges` |
| 拖红区边缘 `moveRedEdge` | 拖红区边缘 = 改绿区补集边界 → 重算 `keptRanges` |
| 长按绿区改长短 `resizeKeeps` | 直接改 `keptRanges[i]` 的 start/end（**零换算**，和 v1 阶段2 同理） |
| 分割线 `cutTapped` | ⚠️ 见 Q3：v2 存储只有 `keptRanges`，「分割」本身不改变数据，需定义语义 |
| 撤销/重做 `BKHistory` | 快照从 `BKProject` 改为 `BKClipBlock`（或整块深拷贝） |

- **风险点（高）**：v1 的 `BKTimeline.*` 全套 helper（`build`/`normalize`/`pieces`/`deriveKeeps`/`keepsToPieces`/`resizeKeeps`/`moveRedEdge`/`moveBoundary`/`toggle`/`mergeSameKind`）在 2A 里**大部分要删或改写**。这些函数依赖 `marks`/`duration`，v2 没有 `marks`。删之前先确认没有任何别处引用（grep `BKTimeline`）。
- **风险点（高）**：`refreshTrack()`（L1096）喂给 `BKTrackView` 的 `pieces`/`splits`/`duration`/`redFolded` 是**单素材波形视图**语义。2A 波剪页仍画单素材波形，可保留这套视图（只改数据来源为 `block.keptRanges` 推导出的 `pieces`）。但 2B 主轨视图是另一套，别混。

### M11 · 模型缺口（必须拍板才能动 2A）

- `playheadTime`（指针复位）
- `displayWidth / displayHeight / sourceRotationDegrees`（导出尺寸与方向；v1 存在 item 上）

- **推荐 (y)** 更符合 v2「Core 干净」原则；但「恢复自动」按钮需要 `autoThresholdDb`，瞬态方案下进页即重跑检测会丢失「手动拖过阈值」的记录 —— 这个取舍要你定（Q4）。

## 3. 风险与铁律（来自工程记忆，动手前必读）

1. **导出铁律（2C 必守）**：帧率必须 `Int(round(fps))`；`videoInput.transform` = 主轨 `preferredTransform`；尺寸与 transform 同源；显示尺寸只用 `naturalSize.applying(preferredTransform)`；双输入交替 append 死锁风险（三趟分离后每趟单输入可缓解）。⚠️ `待改代码清单` ① 的 `expectsMediaDataInRealTime` 单边设置 bug 要在 2C 重写时一并修。
2. **变速坐标铁律**：`out == trackT`（决策⑤）；先折叠再变速（决策④）；`speed` **逐区块**、**禁全局乘数**（`BKTrackModel` 已落实，`setSpeed` 已写）。波剪页/主轨任何「改时长」的操作必须走 `BKTrackModel` 的 `cut/insert/replace/setSpeed/move/setKeptRanges`，**不允许绕过 `foldMap` 直接写源时间**。
3. **本机无 Swift 编译器**：CI（tag 触发）是唯一编译验证。改完 `git commit` 走 API 通道推送（代理端口动态取，见 `MEMORY.md`）。**先 Python 复刻 + 随机不变量验证再落 Swift** 是项目既有铁律（v2 模型已用 `tools/verify_v2_model.py` 5000 轮全绿，改任何一处要回头重跑）。
4. **Core 层禁 `import UIKit`**：`BKDraft.swift` / `BKTrackModel.swift` 已遵守，加字段别破戒（否则进不了 SPM/测试 target）。
5. **发版纪律**：`main` push 不触发 CI，只有 `tag vX.Y.Z` 触发；每次发版同步 `project.yml` 的 `MARKETING_VERSION` + `release/version.json`。同步/手感类问题 CI 验不出，必须真机复核（参考 `待改代码清单` 复盘要点）。
