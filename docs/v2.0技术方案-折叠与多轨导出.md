### ⚠️ 一个必须知道的「刻意反转」

现有 v1.3.4 的选择是 **「全程原片时间、零换算」**（绿区在原片原位，轨道长度不变）。
v2.0 折叠模型要求 **「轨道时间轴 = 折叠后时间」**（总长 = 原长 − Σ 折叠长度，拖动实时变）。

→ **这是刻意推翻 v1.3.4 的核心取舍**。换算重新变成核心，所以：
**坐标映射必须先用 Python 复刻 + 随机不变量验证，全绿才准写进 Swift**（项目既有铁律）。
否则会重演 v1.3.4 那句教训：「我的模型绿了，但真机不绿」。

## 1. 总体架构：三条轨 + 两套时间轴

### 时间轴定义

| 轴 | 范围 | 用途 |
|---|---|---|
| **源时间 (src)** | `0 ~ duration` | 永远不变。**所有标记的存储坐标系** |
| **输出时间 (out)** | `0 ~ displayDuration`<br>= `duration − Σ 折叠长度` | 屏幕显示、播放、导出成品的坐标系 |

### 各轨的坐标系归属（关键决策）

| 轨 | 存什么坐标系 | 理由 |
|---|---|---|
| 主视频轨 | **源时间**（红区 A/B、折叠 leftMark/rightMark） | 标记必须稳定，不随显示变化漂移 |
| **录音轨** | **输出时间** | 录音是「边看成品边录」，录在成品的第几秒就是第几秒 |
| **画中画轨** | **输出时间** | 用户在可见（折叠后）轨道上拖放，看到的位置即成品位置 |

> ⚠️ 待皓哥确认：若希望「调整折叠后 PiP/录音跟着原片内容走」，则改存源时间。
> 推荐**输出时间**（更符合「我摆在成品第几秒」的直觉）。

## 2. 数据模型草案（Core 层，不碰 UIKit）

```swift
/// 一道折叠线：原片里一段被收窄的区间
struct BKFold: Codable, Equatable {
    var id: UUID
    var leftMark:  Double   // 左块结束（源时间），初始 = A，可拖到 C
    var rightMark: Double   // 右块开始（源时间），初始 = B
    var foldedLength: Double { rightMark - leftMark }   // 真实被折叠掉的时长（>0）
}

/// 主视频轨
struct BKMainTrack: Codable {
    var folds: [BKFold]                 // 按源时间升序
    var keptRanges: [Segment]           // 源时间上的保留区间（由 folds 派生）
    var displayDuration: Double         // = duration − Σ folds.foldedLength（动态）
}

/// 叠加轨上的一段（录音 / 画中画）
struct BKClip: Codable, Identifiable {
    var id: UUID
    var start: Double        // 输出时间
    var end: Double          // 输出时间
    var assetLocalID: String? // 画中画素材（相册）
    var fileURL: URL?         // 录音产物（m4a）
    var volume: Float = 1.0   // 录音音量
    var pipRect: BKNormRect?  // 画中画：归一化位置/尺寸 0~1
    var pipRotationDeg: Double = 0
}

/// 叠加轨（录音 / 画中画各一条）
struct BKOverlayTrack: Codable {
    var kind: BKTrackKind    // .recording | .pip
    var clips: [BKClip]      // 按输出时间升序
}
```

**存储原则**：主轨标记存源时间；叠加轨 clip 存输出时间。**不要混**。

## 3. 坐标映射（地基，必须 Python 先验证）

```text
源 → 输出 out(t):
  · t ≤ leftMark[i]                   → t − Σ_{j<i} len_j
  · leftMark[i] < t < rightMark[i]    → 塌到折叠线位置（整段一个点）
  · t ≥ rightMark[i]                  → t − Σ_{j≤i} len_j

输出 → 源 src(u):
  u + Σ_{折叠线输出位置 ≤ u} 对应折叠长度
```

### 必须验证的不变量（写进 `tools/verify_fold_map.py`）

1. `out(0) == 0`
2. `out(duration) == displayDuration`
3. 折叠区内任意源时间 → 同一个输出位置（塌成一个点）
4. 保留区内 `out()` 严格单调递增
5. 往返一致：`out(src(u)) == u`，误差 < 1e-6
6. 布局：轨道总宽 = `Σ 保留长 × pps + 折叠线数 × 线宽`
7. 约束：`leftMark ≤ rightMark`；拖动后 `C ≤ B`、`≥ A`

→ 几千组随机 + 手写脏数据全绿，才落 Swift（照 `tools/preview_cut.py` 的既有做法）。

## 4. 主轨折叠

- **绘制**：保留块按输出时间铺（绿），折叠线画成**指针同宽的一条线**（≈2pt）
- **波形**：保留区的波形取自源时间对应区间；折叠区内的波形**保留不画**，拖出来才显示
- **交互**：点选片段 → 黄框 + 两端把手 + 蓝色悬浮条（`#2F6DF4`）；拖把手 = 改 `leftMark`/`rightMark`
- **实时重算**：每次拖动 → 折叠长度变 → `displayDuration` 变 → 轨道总长实时变
- **与旧数据兼容**：旧草稿 `keptRanges` 迁移成 `folds`（相邻保留块之间即折叠区，`leftMark`=前块 end、`rightMark`=后块 start）

## 7. 导出（皓哥 22:40 定的方案，最后实现）

### 三趟分离 + 长度校验

```text
Pass 1 · 视频
  AVMutableComposition：主轨保留段（源时间）依次 insert
  + 画中画 clip（输出时间）insert
  + AVMutableVideoComposition（主层 + PiP 层）
  → 走现有 BKExporter 手泵（只挂 videoInput）→ tmpVideo.mp4

Pass 2 · 音频
  AVMutableComposition：主轨音频保留段 + 录音 clip（输出时间）
  + AVMutableAudioMix（录音音量 / 接缝淡入淡出）
  → AVAssetExportSession(AVAssetExportPresetAppleM4A) → tmpAudio.m4a

Pass 3 · 校验 + 合成
  |tmpVideo.duration − tmpAudio.duration| ≤ 1帧 + 余量 ?
    ├─ 是 → AVMutableComposition 合 video + audio → 导出最终 MP4
    └─ 否 → 重做 Pass1+Pass2（最多再来 1 轮，共 2 次）
            两次仍不一致 → **报错并停止**（明确报错 + 埋点 + 清理临时文件）
```

### 复用既有铁律（一条都不能省）

- 帧率**必须整数** `Int(round(fps))`（非整数 + B帧 = iOS 26 崩）
- `videoInput.transform` = 主轨 `preferredTransform`（漏了成品必躺下）
- 尺寸与 transform **同源**
- 显示尺寸只用 `naturalSize.applying(preferredTransform)`
- 若某趟仍出现双输入 → 双轨**交替 append**（否则 10 秒死锁）

### 分离导出的额外收益

现在 `drainComposition` 是 video+audio 双输入手泵，死锁风险在这。
分离后**每趟只有一个输入** → 交替 append 的死锁风险自动消失。

### 8.1 横向滚动：半屏余量（皓哥 00:42 要求）

**目的**：保证**指针能从 0 开始、能到末尾结束** —— 两端都能滚到屏幕中央，不会被屏幕边缘切掉。

**参数**（`BKTrackLayout`，纯逻辑，P1 先 Python 验证）

```
W          = 轨道视口宽（= 屏宽 430pt）
leadPad    = W / 2        ← 前半屏余量
trailPad   = W / 2        ← 后半屏余量
trackWidth = displayDuration × pps
contentWidth = trackWidth + W          ← 余量只在视图层

映射：
  contentX(t) = leadPad + t × pps
  screenX(t)  = contentX(t) − scrollOffset
  scrollOffset ∈ [0, trackWidth]        ← 越界必须夹取
```

**验证**：
- `scrollOffset = 0` → **t=0 落在屏幕正中**
- `scrollOffset = trackWidth` → **t=duration 落在屏幕正中**

→ 两端都能到达，指针不被裁切。

**规则**

| 项 | 规定 |
|---|---|
| 四轨共用同一个 layout | 同一 `pps` / 同一 `leadPad` / 同一 `scrollOffset` → **垂直严格对齐** |
| 余量区内容 | **只留白**：不画波形、不画刻度、不画 clip |
| 命中测试 | 点前半屏余量 → 视为 `t=0`；点后半屏余量 → 视为 `t=duration`；**不允许负时间或超界** |
| 吸附锚点 | `0` 与 `duration` 都是合法锚点（见 12.2） |
| 数据层 | 余量**不进数据模型**、**不影响导出**，纯视图层 |

**不变量（写进 `tools/verify_fold_map.py`）**
1. `contentX(0) == W/2`
2. `contentX(duration) == W/2 + trackWidth`
3. `scrollOffset` 越界被夹回 `[0, trackWidth]`
4. 任意 `scrollOffset`，可见区始终覆盖完整视口 `[0, W]`
5. 四条轨的 layout 参数**完全一致**（对齐不变量）

> 若日后想恢复 454pt 预览：把三条叠加轨压到 30pt/条即可（合计 228pt），二者互斥。

## 11. 剪映对照（2026-10-05 00:15 查证，用于校准我们的默认值）

### ① 锚定：剪映用「联动」开关，默认**内容锚定**
- 剪映专业版时间轴右上角有**联动开关（默认开）**，联动设置里可勾选跟随的类型
  （音效/音乐/文本/贴纸/特效/滤镜/调节/画中画）。
- 规则：**移动/删除主轨道素材 → 副轨道同步移动/删除；反过来不成立**。
- 移动端 2.5.1 起也有「关闭联动」开关；另有**波纹编辑**（删除后后续自动前移，默认开）。
- 不联动的场景用「组合」把主轨+副轨打包解决。
→ **修订建议（推翻第1节的原默认值）**：默认**联动（内容锚定）**。
  实现不改存储：叠加 clip 仍存输出时间，拖折叠把手导致折叠长度变化 Δ 时，
  **把该折叠线之后的所有叠加 clip 整体平移 Δ** —— 等价于剪映联动，且零换算。
  对录音尤其正确：解说是描述画面内容的，内容动了配音必须跟着走。

### ② 录音外放：剪映默认**放**，但专业版给了「草稿静音」
- 手机端：录音时预览区播放画面，原声默认会放（教程提示「不想被原声干扰就先关掉/调低」）。
- 剪映专业版录音面板有 **「草稿静音」**（勾选后录音时轨道声音静音）+ **「回声消除」**（建议勾选）。
→ **建议**：照搬「草稿静音」开关，**默认静音**（皓哥用 DJI MIC MINI，外放必串音），并提示戴耳机。

### ③ 画中画图片：剪映**支持**
- 手机端：画中画 → 新增画中画 → 相册选「照片」；双指缩放、拖动定位；
  拖两端白框调时长（**图片可自由延长，视频只能缩短不能拉长**）。
- 另有「切画中画/切主轨」互换、「锁定位置」、「层级」、入场/出场动画。
→ **建议**：保留原方案（图片走「生成静帧视频」缓存），效果等价、实现简单；
  v1 先上视频+图片都行，因为静帧视频方案已经把图片变成视频了。

### ④ 导出：剪映**单趟**，三趟是我们自己的安全网
- 商业 App 内部管线不公开，但必然是单趟合成导出（自研/硬编码管线，有把握做对同步）。
- 我们的「分离导出+长度比对+重试」是**针对自身历史三次同步 bug 的兜底**，不是行业做法，代价是慢约 3 倍。
→ **建议**：v2.0 先按三趟求稳；稳定后加「快速模式 = 单趟导出 + 事后校验长度」开关。

### ⑤ 跨折叠区显示：剪映**没有折叠概念**，此问不适用
- 剪映是「分割 + 删除 + 波纹前移」，删掉的段彻底消失，副轨道靠联动跟随。
- 我们的折叠区在输出时间轴上是一条线（零宽度），输出时间连续 →
  叠加 clip 与录音**自然连续播放**，不存在「跨过折叠区」的问题。

## 12. 吸附（磁吸）功能 + 皓哥 00:23 拍板

### 12.1 剪映手机版的吸附功能清单（查证所得）

时间线右上角**三个开关**：主轨磁吸 / 自动吸附 / 联动。

| # | 功能 | 作用范围 | 行为 | 视觉反馈 |
|---|---|---|---|---|
| 1 | **主轨磁吸**（主轨吸附） | **只作用于主轨道** | 多段素材拖到主轨自动贴紧；裁剪/删除后后续素材**自动前移补缝**；中间插入素材自动腾位。关闭后可自由留白 | 自动贴合，无辅助线 |
| 2 | **自动吸附**（磁吸） | **全轨道通用** | 拖动素材靠近锚点时自动贴紧。用于①同轨两段无缝对接 ②**跨轨道**素材的首/尾对齐 ③吸附到**时间线（播放头）** ④对齐主轨**切口（分割点）** | 出现**蓝色竖线**（吸附到时间线时部分版本为绿线）|
| 3 | 联动 | 主轨 ↔ 附属素材 | 主轨移动/裁剪/删除时，字幕/贴纸/音效同步变动（见第11节） | 素材间显示连接线 |

**吸附锚点汇总**：①同轨相邻素材的头/尾 ②跨轨道素材的开头/结尾 ③时间线（播放头）
④主轨切口（分割点）⑤轨道起点 0 ⑥（主轨磁吸）自动填补缝隙

补充：新版剪映还有「**文字 ↔ 文本朗读音频** 同步吸附跟随」—— 拖文字，音频同步跟随；
拖音频，文字跟随；删除文字时音频同步删除。

### 12.2 我们的磁吸设计（皓哥 00:23 要求）

1. **播放头**（橙色指针）

5. 时间轴**起点 0** 与**末端**

## 13. 产品形态升级（皓哥 02:07）：综合剪辑器 + 气口独立子页面

### 13.1 定位变化
- 从「单素材气口剪辑工具」升级为**综合剪辑软件**
- **主打卖点：自动识别气口**（复用已有 `BKDetector`：音频包络 + Otsu 阈值，已实现）
- 主轨道从「一条素材」改为 **可一次导入多个视频片段**（对齐剪映）

### 13.2 新编辑流程

```
主编辑页（多片段主轨）
   ↓ 单击某片段
悬浮菜单（蓝底胶囊 + 线条按钮）
   ↓ 点「剪气口」【新增按钮】
气口编辑子页面（该片段专属）
   ├ 波形轨道：绿色波形 = 保留；红区覆盖 = 气口
   ├ 自动识别本段气口（进入即跑 BKDetector）
   ├ 手动调整红区边缘
   ├ 红绿切换钮（切换选中区）
   ├ 点击视频区 → 切换该区红绿
   ├ 一键打分割线
   └ 折叠开关 → 一键折叠波形轨道（红区收成线）
   ↓ 返回
主编辑页：该片段按折叠形态显示（视觉变短）
```

### 13.3 相对前面几节的架构影响

| 原方案 | 新方案 |
|---|---|
| 主轨 = 单素材 + 全局折叠 | 主轨 = **多片段**，**每段独立折叠** |
| 红绿标记在主轨上做 | 红绿标记在**片段专属子页面**做 |
| 折叠后整轨重算 | 折叠**按段存储**，主轨显示 = Σ 各段折叠后时长 |
| 点选片段 → 黄框 + 把手 | 单击片段 → **悬浮菜单**（新增「剪气口」） |

### 13.4 坐标映射变成**两级**

1. **片段内**：源时间 → 该片段折叠后时间（沿用第 3 节算法，作用域缩到一段）
2. **主轨**：各片段折叠后**首尾相接**拼接（剪映式多片段主轨）

### 13.5 对其它模块的影响

- **导出**：主轨按片段顺序，逐段 insert 各自 keptRanges
  （与现有 `BKCompositionBuilder` 逻辑一致，外层多一层片段循环）
- **录音轨 / 画中画轨**：不变（仍锚定主轨输出时间、联动、磁吸）
- **文字轨**：❌ **不做**（03:42 删除，所有文字/字幕相关逻辑一并删除）
- **布局（第 8 节）**：不变
- **半屏余量（8.1）**：主轨 `trackWidth` 按「Σ 各段折叠后时长」算
