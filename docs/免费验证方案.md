## 三、方案 A：算法预演（已交付，本机已跑通）

脚本：`bk-clip/tools/preview_cut.py`

### 为什么这一步最关键

这个 App 里，**唯一有可能从头就不成立的部分，就是气口检测算法**。

界面做得再漂亮，如果切出来把字头吃掉、把换气之外的停顿也切了，这 App 就是废的。而这个风险完全可以现在就探清楚 —— 你的 Windows 上 Python + numpy + ffmpeg 全是现成的，我已经替你确认过了。

**先花半小时跑一遍真实素材，比以后花 ¥688 才发现算法不适用要划算得多。**

### 用法

```bash
# 1. 看看检测结果（只出报告，几秒钟）
python preview_cut.py 你的口播.mp4

# 2. 直接导出剪好的视频，拿去听（最有说服力的一步）
python preview_cut.py 你的口播.mp4 --preview

# 3. 生成波形图，肉眼检查红区有没有压到字
python preview_cut.py 你的口播.mp4 --html

# 4. 一次出齐：报告 + 试听视频 + 波形图 + 切点表
python preview_cut.py 你的口播.mp4 --all
```

### 报告怎么看

脚本会打印 Otsu 算出的原始阈值和实际使用的阈值，**这两个数的差值本身就是诊断信息**：

| 情况 | 说明 | 该怎么办 |
|---|---|---|
| 两者接近（都落在 -50~-25dB） | 素材音量分布正常 | 默认值就行，不用管 |
| **两者差很多** | 这段素材底噪反常，经验区间不适用 | 已被自动夹逼兜住，但建议手动试几个阈值对比 |
| 删掉比例 > 50% | 阈值过于激进 | 手动指定 `--threshold -35` 之类再跑 |
| 「6dB 余量否决」数量很大 | 素材动态范围小（比如音乐伴奏） | 这类素材本身就不适合自动去气口 |

### 一步一步调参

```bash
python preview_cut.py 素材.mp4 --threshold -45 --preview   # 保守：只切很干净的气口
python preview_cut.py 素材.mp4 --threshold -38 --preview   # 激进：切得更狠
```

把 -45 和 -38 这两档导出的片段对比着听，找到你觉得舒服的那个电平，**这个数字就是将来 App 里默认阈值的依据**。

### 这个脚本就是 App 的算法

脚本里实现的是 Swift 端的等价版本，参数与 App 定稿完全一致：

| 参数 | 值 | 位置 |
|---|---|---|
| 最短气口 | 0.20 s | `MIN_GAP` |
| 最短片段 | 0.60 s | `MIN_SEG` |
| 头尾留白 | 0.10 s | `PAD` |
| 阈值夹逼区间 | -50 ~ -25 dB | `CLAMP_LOW / CLAMP_HIGH` |
| 局部对比度余量 | 6 dB | `CONTRAST_DB` |
| RMS 窗长 / 步进 | 20 ms / 10 ms | `FRAME_MS / HOP_MS` |
| 接缝淡入淡出 | 15 ms | `export_preview` 里的 `fade` |

**改这里的数 = 改 App 的行为。** 等你用真实素材把参数调舒服了，这套数直接搬进 Swift，不用再试一遍。

### 已验证（本机实跑，非纸面推演）

合成素材含四种陷阱：正常气口 / 0.15s 超短气口 / 被 0.35s 短句夹住的两个气口。结果：

- 0.15s 短气口 → 正确丢弃 ✓
- 短句两边的两刀 → 正确撤销（不产生碎片）✓
- Otsu 算出 -61dB 被夹逼到 -50dB → 兜底机制生效 ✓
- `--preview` 导出成功，12.17s → 11.97s，时长对得上 ✓

（过程中揪出并修掉一个 ffmpeg concat 的接线错误，那个 bug 会直接让导出失败。）

局限说清楚：Web 原型验证不了**相册读写、导出到相册、4K 长视频的真实性能**。这三件事必须真机。

## 五、为什么不推荐 C 和 D

**C（云 Mac 按小时租 + 免费 Apple ID）** 技术上可行，MacinCloud / AWS EC2 Mac 都能租。但有三个问题：

1. **7 天就得重签一次** —— 免费账号的签名有效期就是 7 天，过期 App 打不开
2. **必须有一台电脑常开 AltServer**（或配合 AltStore / SideStore 自动重签），等于把一件简单的事变成长期运维
3. App ID 数量受限（免费账号 7 天内只能建有限个 App ID），调试期很容易撞上限

租 Mac 一个月调试几次，花费可能就逼近 688 了，还多了一堆折腾。**属于「省钱但赔进去时间」的典型。**

**D（二手 Mac mini + 免费 Apple ID）** 不推荐给新手：花了两千五，结果还不能发给团里的人（免费账号无法 Ad Hoc 分发），等于主要需求没解决。要么 ¥0（走 A+B），要么 ¥688 一步到位。

## 六、技术上有、但不建议走的一条：AltStore

顺带说清楚，免得你以后看到别的教程觉得我漏了：

**AltStore** 能用免费 Apple ID 把 ipa 侧载到 iPhone，支持 Windows（AltServer），过期能自动重签。看起来是绕过 ¥688 的办法，但 ——

- 它**替代的是「分发资质」，不是「编译能力」**。你仍然要先有 ipa，而 SwiftUI 项目只能用 Xcode 编译 → **还是需要 Mac 或云 Mac**
- 7 天重签 + App ID 配额，长期维护成本远高于 688/年

所以：**皓哥的情况（无 Mac）用它也不省钱，只多折腾。** 不推荐。

（另：Swift Playgrounds 免费且能在 iPad 上跑 SwiftUI，但它是受限沙盒，用不了 AVFoundation 全套和相册导出，对这个项目没意义。）
